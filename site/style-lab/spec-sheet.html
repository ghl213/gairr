第一条适用范围

GAIRR 适用于需要在本机完成代码理解、修改与验证的开发场景，尤其是以下三类：

  • 数据敏感：金融、医疗、政务项目，源码与数据库不允许出内网。
  • 离线受限：内网机房、客户现场、出差途中，没有稳定的外网连接。
  • 成本敏感：高频重复的开发任务希望由本地模型承担，复杂任务再切云端。

不适用于：需要多人实时协同编辑的场合（GAIRR 是单机程序，协同靠 Git），以及 macOS / Linux 环境（见附注）。

Note 批注本地部署不是"退而求其次"。当出网本身是风险时，能离线跑完一整条任务链就是硬指标。

第二条系统构成

系统由四层构成：工具层、检索层、编排层与沉淀层。各层均可单独查看运行痕迹。

表 2-1 部件清单
层部件职责
工具层8 个内置工具Read / Write / Edit / Grep / Glob / Bash / ListDir / DbQuery，命名兼容开放技能规范
检索层五层混合检索历史关联 → 符号标签 → 符号定义 → 文件摘要 → 向量索引，优先命中省 token 的前层
检索层项目地图增量扫描生成文件摘要与功能架构树；缺失注释由模型补写，只存 .gairr/notes.json，不改源码
编排层计划分解复杂任务拆为叶子任务，逐个执行并审查，支持命令行无人值守
编排层Skill 生态SKILL.md 开放规范，启动仅注入一行描述，用到才读全文；/技能名 可强制触发
沉淀层经验积累失败记录与环境坑写入项目经验，同类任务下次自动带上
沉淀层文档同步代码变更后自动刷新关联的架构与功能文档

所有运行痕迹集中存放在项目根的 .gairr/ 目录内：

.gairr/
├── architecture.json   功能架构树（L0 项目 / L1 子系统 / L2 功能分类 / 叶子）
├── map.json            项目地图：文件摘要与符号索引
├── notes.json          模型补写的说明（不写入源码）
├── tasks.json          自动任务清单，随项目隔离
├── sessions/           会话记录与任务级备份
└── embed-index.bin     向量索引
Note 批注换项目就是换一个 ProjectRoot，经验与任务清单各自独立，不会串味。

护栏实现在框架层，不依赖模型自觉。下列四条在任意模式下均生效：

第四条运行工序

一次完整任务按下列五步执行，顺序不可调换：

  1. 4.1
    接后端
    在 config.ini 填本地端点或云端 Key。换后端只需改 BaseUrl 与 Model 两行。
  2. 4.2
    下任务
    在会话区一句话下达，或用命令行无人值守执行：gairr -t "任务描述" -p D:\myproject
  3. 4.3
    定位
    先查项目地图与五层检索，确认要改的文件与行号，再动手；避免凭记忆猜路径。
  4. 4.4
    改动并验证
    改前备份、改后编译验证；失败自动进入下一轮修复，未通过不算完成。
  5. 4.5
    收尾
    发送通知，写入本轮经验；命令行模式以退出码收束：0 成功 / 1 失败 / 2 取消或超时。
REM 无人值守示例：转码 + 编译验证 + 通知
$ gairr -t "把 src 下所有源码转为 UTF-8，并跑编译验证" -p D:\myproject
[14:01] 任务启动 · 已对 src/ 下 50 个文件做任务级备份
[14:06] Edit src/Utils.pas   ✗ 编译失败：标识符未声明 → 自动进第 2 轮
[14:09] 全部完成 · 50/50 · 编译通过 · 已发送钉钉通知
Note 批注下达任务之后可以离开工位。改 50 个文件这种活不用守着屏幕，完事钉钉会叫你。

附注已知限制

  • 当前仅支持 Windows；macOS / Linux 在路线图上，尚无时间表。
  • 单机程序，不含多人实时协同；团队共享通过 Git 与本项目的 .gairr/ 目录完成。
  • 本地模型能力受量化与显存限制，超长上下文推理仍建议切云端通道。
  • 向量索引为可选层，关闭后四层检索照常工作，仅语义模糊查询命中率下降。
